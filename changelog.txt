# Changelog — Câmara Municipal de Ipiranga do Piauí

Todas as alterações relevantes do projeto são registradas neste arquivo.

O projeto foi desenvolvido de forma incremental ao longo de três trabalhos acadêmicos. Os dois primeiros trabalhos correspondem à construção e ao aprimoramento da aplicação original com HTML, CSS e JavaScript. O terceiro trabalho corresponde à modernização da aplicação com React, Vite e arquitetura SPA.

## [3.0.1] — Trabalho 3 — Parcial 2 — 27/11/2026

### Contexto

Esta versão registra a segunda etapa do Trabalho 3. A estrutura SPA criada na Parcial 1 foi mantida e recebeu comunicação assíncrona para carregar os dados do sistema.

### Adicionado

- Arquivo public/data/vereadores.json com os dados dos vereadores.
- Arquivo public/data/sessoes.json com a agenda de sessões.
- Serviço src/services/api.js para centralizar requisições HTTP GET com a Fetch API.
- Carregamento assíncrono dos vereadores e das sessões.
- Estado visual de carregamento.
- Tratamento de respostas HTTP com erro.
- Botão "Tentar novamente" quando o carregamento falha.
- Controles para aceitar, recusar, consultar e limpar a preferência de cookies.

### Modificado

- O componente `src/App.jsx` deixou de importar dados diretamente de um arquivo JavaScript.
- A tela de vereadores passou a consumir `/data/vereadores.json`.
- A tela de sessões passou a consumir `/data/sessoes.json`.
- O README foi atualizado com a estrutura e o funcionamento da Parcial 2.
- Os estilos foram atualizados para exibir mensagens de erro da comunicação assíncrona.

### Funcionalidades mantidas

- SPA com React Router.
- Busca de vereadores por nome ou partido.
- `sessionStorage` para manter a busca durante a sessão.
- `localStorage` para manter os dados de contato.
- Cookies para registrar a preferência do usuário.
- Responsividade, acessibilidade e identidade visual da Parcial 1.

### Endpoints estáticos utilizados

- `GET /data/vereadores.json` — retorna a coleção de vereadores.
- `GET /data/sessoes.json` — retorna a coleção de sessões.

### Validação

- O comando `npm run lint` foi executado sem erros.
- O comando `npm run build` foi executado com sucesso.

## [3.0.0] — Trabalho 3 — Parcial 1 — 20/11/2026

### Contexto

Esta versão corresponde à Parcial 1 do terceiro trabalho da disciplina Programação para a Web I. Ela registra a primeira etapa da evolução do projeto; a implementação completa do Trabalho 3 será concluída nas próximas entregas. O objetivo é dar continuidade à aplicação desenvolvida nos dois trabalhos anteriores, mantendo o tema Câmara de Vereadores e adaptando a estrutura existente para a utilização de ferramentas modernas de desenvolvimento frontend.

### Adicionado

- Migração da aplicação original para React.
- Configuração do Vite como ferramenta de desenvolvimento e build.
- Implementação de uma Single-Page Application (SPA).
- Implementação de navegação no cliente com React Router.
- Criação de rotas para as áreas de início, Câmara, vereadores, sessões, projetos e leis, transparência, armazenamento e contato.
- Organização da interface em componentes React reutilizáveis.
- Configuração do Bootstrap como biblioteca de estilização e apoio ao layout responsivo.
- Configuração do ESLint para análise estática do código.
- Configuração do Prettier para padronização da formatação.
- Inclusão de instruções atualizadas de instalação, execução e validação no README.
- Inclusão do arquivo `PLANO-ENTREGAS.md`, com a divisão entre as entregas parciais e a entrega final.

### Modificado

- Substituição da estrutura baseada em uma única página HTML com manipulação direta do DOM por uma aplicação React componentizada.
- Substituição da navegação por âncoras por rotas gerenciadas no lado do cliente.
- Reorganização dos dados de vereadores e sessões no arquivo `src/data/conteudo.js`.
- Atualização da estrutura de diretórios para o padrão de um projeto React com Vite.
- Atualização do README para documentar as novas ferramentas e os comandos do projeto.
- Atualização do processo de desenvolvimento para utilizar `npm install`, `npm run dev`, `npm run lint` e `npm run build`.

### Funcionalidades mantidas

- Consulta e filtragem dos vereadores por nome ou partido.
- Persistência do termo de pesquisa utilizando `sessionStorage`.
- Persistência do nome e do e-mail do contato utilizando `localStorage`.
- Limpeza dos dados armazenados no navegador.
- Apresentação das informações institucionais da Câmara.
- Exibição da tabela de sessões legislativas.
- Áreas de projetos, leis, documentos e transparência.
- Formulário de contato com validação dos campos obrigatórios.
- Layout responsivo e recursos básicos de acessibilidade.

### Validação

- O comando `npm run lint` foi executado sem erros.
- O comando `npm run build` foi executado com sucesso.
- A aplicação pode ser executada localmente com `npm run dev`.

### Próximas alterações previstas para a Parcial 2

- Implementação de comunicação assíncrona com a Fetch API utilizando requisições GET.
- Criação de arquivos JSON na pasta `public/data` para servir os dados da aplicação.
- Inclusão de estados de carregamento e mensagens de erro nas requisições.
- Finalização do gerenciamento da preferência de cookies.
- Atualização completa do relatório no modelo da Sociedade Brasileira de Computação (SBC).
- Registro das versões das ferramentas, dificuldades encontradas e soluções adotadas.

## [2.0.0] — Trabalho 2 — 23/10/2026

### Contexto

Esta versão corresponde ao segundo trabalho da disciplina. A aplicação institucional criada no Trabalho 1 foi aprimorada com JavaScript, recursos de interatividade e armazenamento de dados no navegador.

### Adicionado

- Implementação de interatividade com JavaScript.
- Geração dinâmica dos cartões de vereadores a partir de arrays e objetos.
- Pesquisa de vereadores por nome ou partido.
- Geração dinâmica da tabela de sessões legislativas.
- Validação do formulário de contato.
- Mensagens de sucesso e erro para o formulário.
- Utilização de `localStorage` para salvar o nome e o e-mail do contato.
- Utilização de `sessionStorage` para salvar a pesquisa de vereadores durante a sessão da aba.
- Utilização de cookies para registrar a preferência do usuário.
- Seção de armazenamento de dados no navegador.
- Botões para aceitar ou recusar cookies.
- Botão para limpar os dados armazenados.
- Exibição do estado dos dados salvos no navegador.
- Destaque da seção ativa no menu de navegação.
- Botão para retornar ao topo da página.

### Modificado

- Atualização do HTML para incluir os elementos necessários às funcionalidades JavaScript.
- Atualização do CSS para estilizar a pesquisa, o menu ativo, as mensagens, os cartões de armazenamento e os controles de cookies.
- Criação e inclusão do arquivo `script.js`.
- Atualização da documentação para descrever as novas funcionalidades.

### Observações

- O formulário de contato possui finalidade demonstrativa e não encaminha mensagens para um servidor real.
- Os dados de vereadores e sessões permanecem armazenados diretamente no código JavaScript.
- O `localStorage` persiste os dados até que sejam removidos pelo usuário.
- O `sessionStorage` mantém os dados enquanto a sessão da aba estiver ativa.
- Os cookies utilizados têm finalidade acadêmica e demonstrativa.
